# Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Report vulnerabilities privately through [GitHub Security Advisories](https://github.com/heartcodeprotocol/heartcode-protocol/security/advisories/new). If that form is unavailable, do not disclose vulnerability details publicly; contact the maintainers through the repository's current private contact channel.

Include only what is needed to reproduce and assess the issue:

- affected file, component, workflow, or integration;
- impact and attack preconditions;
- reproducible steps or a minimal proof of concept;
- affected commit, deployment, or version;
- suggested mitigation, when known.

Never include live credentials, API keys, cookies, personal information, confidential prompts, proprietary data, or private user content.

## Scope and response

The maintainers will assess the report's reproducibility and scope, coordinate a fix when appropriate, and document a safe resolution. Response time depends on impact and available evidence; no fixed remediation deadline is guaranteed.

The protocol is an open behavioral-evaluation standard, not a certification program or a guarantee that an implementation, provider, model, dependency, or integration is secure.

See [SECURITY_AND_RESILIENCE.md](SECURITY_AND_RESILIENCE.md) for the project's trust boundaries and limitations.
