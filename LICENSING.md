# Licensing Posture

**Status:** Public clarification pending selection of an explicit license  
**Date:** 2026-08-18

Heartcode Protocol is published for public inspection, discussion, criticism, citation, and empirical review. The project uses the term **open standard** to describe the public, versioned specification and its public review process.

## Current legal posture

This repository does **not currently contain an explicit LICENSE file** and the project has not yet adopted a specific open-source, open-content, or standards-document license for the repository contents.

Public availability on GitHub should therefore not be interpreted as a grant of permission to copy, modify, redistribute, sublicense, or create derivative versions of protected repository content beyond rights that otherwise apply under applicable law.

The absence of an explicit repository license is a known adoption-readiness limitation. The project intends to make the licensing posture explicit before making broad claims about legal reusability or standardized third-party redistribution.

## What is encouraged now

The project welcomes:

- public reading and technical criticism;
- links and citations to the public specification;
- reproducible test cases and counterexamples submitted through the public issue tracker;
- proposals for protocol changes through the documented contribution process;
- discussion of independent implementations and interoperability requirements.

This document does not itself grant a software or content license.

## Future license decision

Selecting an explicit license is a separate governance and intellectual-property decision. It should account for at least:

- reuse of the protocol specification text;
- independent implementations of the protocol;
- contributions from third parties;
- trademark and project-name use;
- compatibility with any future standards-body participation;
- the separate private status of the Validator Master reference implementation.

Until that decision is made and recorded in a versioned repository change, claims about Heartcode being "open" should refer to the transparency and public review of the specification, not to an assumed legal permission to reuse repository contents.

This page is a project-status clarification, not legal advice.
